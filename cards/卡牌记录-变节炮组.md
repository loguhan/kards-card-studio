## 2. 效果实现

一个函数，挂在 `OnAfterAttack`：

```
OnAfterAttack(defenderCard, wasShockAttack, attackCost)      // 事件签名，override BaseCardObject
│
├─ damage = Self.getTotalAttack()                            // 含增益的总攻击力
├─ mySide = Self.side                                        // 自己当前所属方
├─ cardFunction.GetLocationCardBySide(out friendlyHq,         // 取友方总部
│                                     out friendlyHqId, mySide)
├─ cardFunction.DamageCard(friendlyHq, damage, Self.CardID,   // 友方总部吃同样的伤害
│                          false, false, false, out targetDestroyed)
└─ cardFunction.TakeControlOfEnemyUnit(Self, Self.CardID)     // 控制权移交给对方
```

编译产物 `manifest/blueprints/card_unit_sov_defector_artillery.blueprint.json` 实测结构：

```
package: /Game/Blueprints/Cards/Mods/Soviet/units/card_unit_sov_defector_artillery
asset  : card_unit_sov_defector_artillery
parent : /Script/kards BaseCardObject

function: OnAfterAttack | override: BaseCardObject
   var  defenderCard / wasShockAttack / attackCost      (Input)
   var  mySide / friendlyHq / friendlyHqId / damage / targetDestroyed  (Local)
   call  getTotalAttack            args=1  dispatch=SelfFinal
   [assign]
   call  GetLocationCardBySide     args=3  dispatch=ObjectVirtual
   call  DamageCard                args=7  dispatch=ObjectVirtual
   call  TakeControlOfEnemyUnit    args=2  dispatch=ObjectVirtual
```

### 为什么这样写（对游戏本体的核对）

这几条结论都不是猜的，是把游戏自己的 `BP_CardFunctions` 反编译结果读出来核对的：

| 决策 | 依据 |
|---|---|
| 挂 `OnAfterAttack` | `BP_CardFunctions_ExecuteOnAfterAttackEvents.cpp` 里，对未压制的攻击者会调用 `attacker.OnAfterAttack(defender, afterShockAttack, attackCost)`。压制的单位不会触发——这是正确的游戏行为。 |
| 伤害量取 `getTotalAttack()` | `OnAfterAttack` 签名里没有伤害值，只有 `defenderCard / wasShockAttack / attackCost`。要拿真实伤害得用 `OnOtherCardAttacks`，但那需要往 `usedTriggers` 注册触发（编译器不支持），所以退一步用自身总攻击力。对 1/1 炮兵来说等价。 |
| 友方总部用 `Self.side` + `GetLocationCardBySide` | 不用 `GetClientSide`——那是"本地客户端视角"，联机下客户端和出牌方可能不是同一侧。 |
| 控制权用 `TakeControlOfEnemyUnit` | `BP_CardFunctions_TakeControlOfEnemyUnit.cpp` 里它实际就是 `ChangeUnitOwnership(card.CardID, instigatorID, card.side, card.GetOppositeSide(), ...)`，也就是**把这张卡翻到它的对侧**——正好等于"移交给对方"。`instigatorID` 只是归因，传 `Self.CardID`（自己叛变）语义自洽。 |

### 已知取舍

- **伤害量用的是总攻击力，不是实际造成的伤害。** 如果被 `OnCardDealDamage_ModifyDamageDealt` 之类的效果改了实际伤害，本卡仍按自己的攻击力扣友方总部。要精确得改走 `OnOtherCardAttacks` + `usedTriggers`，编译器目前不支持。
- **被压制时不触发**（`isSuppressed == true`）。这是引擎行为，不是 bug。
- **卡图 / 历史照片没有配**（`Visuals` 未设置），游戏里会用默认占位。

## 4.5 事故：pak 里的 AssetRegistry.bin 把整个卡库覆盖没了

**现象**：第一次部署后，游戏里**所有卡牌都消失了，包括原有的**。

### 走过的弯路

| 尝试 | 结果 |
|---|---|
| 卡编译器默认 profile 的基底注册表（15,867 资产） | 全丢 —— 基底本身就比游戏的小 |
| 换成游戏真实注册表当基底重建 profile（16,314 资产，超集） | 仍全丢 |
| 把哈希按名字填回（30,446/30,451）+ 恢复 hashVersion | 仍全丢 |
| pak 里放**游戏原版逐字节**的注册表 | **正常** —— 证明补丁包里放注册表这件事本身没问题 |

### 真正的根因

`KardsCardCompiler` 依赖的那套 `UAssetRegistry`（从 CUE4Parse 移植，只读解析器）**回写时把 name 哈希表整个写成 0**：

```csharp
// FAssetRegistryWriter.cs:153-154
_w.Write((ulong)0);                                // hashVersion（读取时忽略）
for (var i = 0; i < num; i++) _w.Write((ulong)0);  // hashes（读取时忽略）
```

实测对比（header 后 24..260000 字节）：

| 文件 | 哈希区零字节 | 最长连续 0 |
|---|---|---|
| **游戏原版** | 3.3% | 4 |
| 卡编译器重序列化 | **96.8%** | **243,618** |
| CCB-TEAM 重序列化 | **96.8%** | **243,591** |

而且它还会**重建 name 表**：顺序全变、丢 113 个名字。游戏查资产名靠这张表，全零 → 整张表作废 → 卡库全空。

### 正解：`AssetRegistryTool`（UE 编辑器插件）

RAR 里 `改bin插件\AssetRegistryTool-main.zip` 就是答案。它是 **UE 5.6 编辑器插件**，在编辑器进程里用 **UE 自己的 `FAssetRegistryState` 序列化器**做合并，所以哈希表天然正确。

```powershell
# 1) 装进工程
Copy-Item <AssetRegistryTool> (UE 工程)\Plugins\ -Recurse
# 2) 在 kards.uproject 里启用它（同时禁掉 FullMatchRuntimeProbe，否则它会弹窗打断启动）
# 3) 合并：host = 游戏原版注册表，donor = 含新卡的编译器产物
UnrealEditor-Cmd.exe (UE 工程)\kards.uproject -run=AssetRegistryTool Merge `
  -HostAssetRegistry=<游戏原版 AssetRegistry.bin> `
  -AssetRegistry=<编译器产物 AssetRegistry.bin> `
  -OutputAssetRegistry=<输出> `
  -FilterPaths=/Game/Blueprints/Cards/Mods `
  -OverwriteExistingAssets -unattended -nopause -nosplash -UTF8Output
```

输出日志：
```
LogAssetRegistryTool: Display: Host assets: 16312, Donor assets: 16314
LogAssetRegistryTool: Display: ✅ Successfully saved cooked-style AssetRegistry to: ... (size: 6836211 bytes)
```

### 对比结果

| 注册表 | 大小 | nameCount | 哈希区零字节 | 含我的卡 |
|---|---|---|---|---|
| 游戏原版 | 6,473,556 | 30,559 | **0.38%** | ✗ |
| 卡编译器输出 | 5,683,038 | 30,451 | 100% | ✓ |
| **AssetRegistryTool 合并** | **6,836,211** | 30,472 | **0.38%** | **✓** |

### 教训

- 打补丁 pak 前，**必须确认里面每个文件都是"超集"或"纯新增"**，绝不能覆盖原版资源
- 但"超集"要看**结构**，不是看数量 —— 资产数是超集、哈希表全零，照样把卡库搞没
- **cooked 游戏的注册表只能用引擎自己的序列化器写**，第三方解析器的"回写"能力不可信
- 参照 `zz_ChinaExperiment_2_P.pak`：它 18 个文件里**一个 AssetRegistry.bin 都没有**，所以一直安全
- 出事后一键回滚：把 pak 移出 `Paks\` 即可

## 5. UE4SS 桥接协议（踩坑记录）

`<UE4SS>` 的桥走文件 spool，但要真正驱动它，光写命令文件不够。三条硬性要求：

| 要求 | 报错 | 说明 |
|---|---|---|
| **必须登记 `commands/index.json`** | 命令文件一直躺在 `commands/` 不动，无 ack | `index.json` 是 server 侧拥有的待办 id 列表；不登记就永远不被处理 |
| **必须带 `session_nonce`** | `session_nonce_mismatch` | 从 `Output/session.json` 读，每次游戏重启会变 |
| **必须带 `expires_at_unix_ms`** | `command_expired_or_missing_expiry` | 数字；必须 `> now` 且 `<= now + 120000` |

可用的客户端：[bridge.py]((仓库)\bridge.py)

```powershell
python bridge.py ping
python bridge.py eval "<lua>"
python bridge.py raw '{"kind":"get_property","target":"...","property":"kredits"}'
```

**避坑**：不要在 `eval` 里遍历整个函数表（`GetClass():GetFunctions()`）——实测会把游戏线程卡住并导致游戏退出。用 `get_property` / `describe_object` 这类定点命令。

## 6. 启动游戏的方式（重要）

**别让我启动。** 实测三次都不对：

| 试过的方式 | 结果 |
|---|---|
| `Start-Process kards.exe`（启动器桩） | 桩拉起 `kards-Win64-Shipping.exe` 后自己退出 → 作业对象回收 → 游戏被带走，活 ~4 分钟 |
| `Start-Process kards-Win64-Shipping.exe` 直启 | `操作已被用户取消`（需要提权，而本会话审批被禁用，UAC 自动取消） |
| 后台作业 + `while (Get-Process ...)` 保活 | 游戏能起，但 Steam 没运行时仍会自行退出；而且会冒出 `-154` 第二个实例 |

**结论：游戏由用户自己启动。** 我只负责把 pak 放到位，不碰进程。

如果确实需要我这边保活，唯一验证过能用的写法是让 shell 一直挂着：

```powershell
Start-Process -FilePath '<GAME>\kards.exe' -WorkingDirectory '<GAME>'
while (-not (Get-Process -Name 'kards-Win64-Shipping*' -ErrorAction SilentlyContinue)) { Start-Sleep 2 }
while (Get-Process -Name 'kards-Win64-Shipping*' -ErrorAction SilentlyContinue) { Start-Sleep 5 }
```

但这只解决"作业对象回收"，解决不了"Steam 没运行导致游戏自行退出"。
